The upstream v1.6.0 repository does **not** commit its generated model data:
`packages/ai/catalog/README.md` says `src/providers/data/<provider>.json` is
gitignored and generated by `npm run generate-models`. Released clients fetch the
built catalog from pi.dev, so the live API is the correct ground truth for a catalog
diff. `google/gemini-4-hydrogen` is absent from the v1.6.0 source tree and from our
pinned 1.5.2 snapshot, but present in the live catalog that v1.6.0 clients use.

## Deliberate scope (deviation from full sync)

- **Additive only.** The live catalog also changes fields on 665 entries the port
  already had (591 `compat` updates, 115 cost changes, 64 max-token changes,
  59 base URLs, 30 context windows, 18 names). Those are *not* applied: the port
  is pinned to upstream 1.5.2 semantics, and wholesale replacement would change
  wire behaviour (developer-role / thinking-format defaults, pricing) without a
  code port. Apply them only with a matching code-parity wave.
- **95 port-only entries retained.** Models removed from the live catalog between
  the 1.5.2 snapshot and today stay in the embedded catalog so existing sessions
  and `--models` patterns keep resolving. This is a catalog-only deviation.
- **Catalog reach is not wire reach.** The new classifiers use System One APIs
  whose wire paths are not ported (see `pi-ai/src/providers/classifier.rs`); they
  are listed because upstream lists them, and they error honestly if invoked.
  Chat and image additions use APIs the port already streams.
- `pi-rs` remains pinned to upstream **1.5.2** semantics; v1.6.0 here is a catalog
  data source only. The XDG `pi-rs` roots remain the headline deviation.
